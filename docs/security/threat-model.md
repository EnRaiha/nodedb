# Threat model

This document describes the security boundaries of a running NodeDB server. It is a maintenance guide: when an endpoint, wire message, storage format, or authorization path changes, update the relevant row and keep the invariants below true. Paths and symbols are intentionally named without line numbers so they remain useful as the implementation evolves.

## Scope and security objectives

NodeDB protects the confidentiality and integrity of tenant and database data, credentials, authorization policy, metadata, replication state, and audit/CDC records. It also protects service availability within configured resource limits and preserves durable-write and recovery semantics.

The main actors are:

- **Unauthenticated network clients**, which can send malformed, oversized, replayed, or adversarial requests.
- **Authenticated users, API-key holders, service accounts, and mTLS/JWT principals**, which may be authorized for only a subset of databases, collections, and operations.
- **NodeDB-Lite sync peers**, whose sync and CRDT input remains untrusted until its peer identity, tenant, collection, and operation are admitted.
- **Cluster peers and joining nodes**, which are trusted only after cluster transport identity and join admission succeed.
- **Operators and automation**, which administer keys, TLS, backups, deployment configuration, and monitoring.
- **External delivery targets** (webhooks and Kafka), which are outside NodeDB's trust boundary.

The following are protected assets:

| Asset | Primary protection goal |
| --- | --- |
| User records, documents, vectors, arrays, time-series, indexes, and query results | Tenant/database isolation, collection permission checks, RLS, and durable storage integrity |
| `AuthenticatedIdentity`, credentials, API keys, JWT/OIDC claims, mTLS certificates, sessions, and join tokens | Verification before use, server-side authority binding, revocation/expiry handling, and no client-created identity |
| Catalog descriptors, leases, permissions, roles, RLS policies, and Raft membership | Database-scoped metadata authority, capability dispatch, lease/drain coordination, and replicated admission |
| WAL, segments, snapshots, catalog and Raft files, CDC offsets, audit data | Format validation, corruption detection or authenticated encryption where configured, recovery/quarantine/fail-stop behavior |
| Cluster and sync frames | Authenticated peer admission, framing and size limits, transport integrity, and operation-specific authorization |
| Availability | Bounded bodies/queues/streams, deadlines, admission control, backpressure, and phased shutdown |

## Mandatory invariants

1. **Authenticate before authorizing; authorize before dispatch.** Client entry points obtain an `AuthenticatedIdentity` only through their protocol authentication path. They authorize planned `PhysicalTask`s through `control::server::shared::authorization::authorize_task_set` (or the matching collection-capability helper), receive an `AuthorizedTaskSet`, and dispatch only the contained `AuthorizedTask`s. `dispatch_authorized_to_data_plane` consumes one such capability; it is not a general client dispatch API.
2. **Identity authority is server-owned.** `AuthenticatedIdentity` is constructed by credential verification and trusted internal services, not from request fields. `JwtValidator::validate` and external-provider binding use a server-configured tenant; an asserted token tenant is not authoritative. `session_auth::build_auth_context` derives context from the authenticated connection.
3. **A database name is selection, not authority.** A selected database must resolve in the catalog and be allowed by `AuthenticatedIdentity::can_access_database`; collection and plan authorization bind the database ID and tenant ID carried by the task. Database-scoped descriptors, CDC registrations, routing, and leases preserve that pair.
4. **RLS never grants access.** RBAC/collection permission is checked first; RLS then filters or denies according to the authenticated `AuthContext`. `X-On-Deny` (and SQL/session `ON DENY`) only selects the presentation of an RLS denial—silent filtering versus an error. It cannot grant database, RBAC, or collection access and cannot bypass authorization.
5. **Decode before allocation and execution is bounded.** Network parsers must validate framing, lengths, nesting, field counts, and semantic ranges before allocating or forwarding input. Bounded queues, body limits, stream limits, timeouts, request guards, and backpressure protect each plane.
6. **Plans and metadata do not outlive their authority.** A descriptor/metadata lease is held while planning and using its database-scoped descriptor; DDL drains conflicting scans through `control::lease` and `bridge::quiesce`. Cached plans are re-authorized for the current query context (`control::gateway::authorized_plan_for_context`).
7. **No cross-plane bypass.** The Control Plane performs authentication, parsing, planning, and authorization; the Data Plane executes admitted physical work; the Event Plane consumes committed write events and returns work through the authorized Control-to-Data path. The bounded SPSC bridge and Event Bus are the crossing points.
8. **Failure closes access or readiness.** Authentication, authorization, decoding, catalog lookup, and lease failures do not fall back to another tenant/database or an unscoped execution path. Startup gates keep non-health traffic unavailable until ready; shutdown stops admission, drains/aborts bounded work, and closes in order.

## Trust boundaries and entry-point map

All client payloads, headers, credentials, cursors, and offsets are untrusted input. The table maps each supported surface to its neutralizing boundary. “Authorization” means database/tenant binding plus the shared capability check, not merely a successful login.

| Entry point | Untrusted input | Neutralizing boundaries and symbols |
| --- | --- | --- |
| **pgwire** | Startup parameters, passwords/TLS client certs, SQL, prepared values, COPY filenames/paths and row data | `control::server::pgwire::{listener,connection,connection_identity}` authenticates the connection; `session_auth::{authenticate,build_auth_context_with_session}` binds identity/session/database; SQL routes through `nodedb_sql::plan_sql`, `authorize_task_set`, and authorized dispatch. COPY and file-oriented operations must be treated as server-side path authority and checked before opening/allocating. Parser, protocol, numeric-narrowing, request, and stream limits reject malformed or excessive input. |
| **HTTP JSON, NDJSON, query streams, and resource APIs** | `Authorization`, `X-NodeDB-Database`, `X-On-Deny`, query parameters, SQL, JSON/NDJSON body, uploads, and stream chunks | `http::auth::{resolve_identity,resolve_auth}` validates bearer credentials; `http::routes::query::resolve_database_id` resolves the selected database; handlers build an authenticated context, authorize the target operation, then use the gateway/authorized dispatcher. This row also covers the dedicated `document`, `auth`, `session`, `key`, `wasm`, `subscribe`, `status`, and `cluster`/debug route modules: each must make an explicit role/capability and body-limit decision rather than inheriting authority merely from routing. WASM upload validates administrator authority and bounded module content before persistence. `http::auth::apply_on_deny_header` accepts only the trimmed, case-insensitive `SILENT` or `ERROR` presentation tokens; SQL/session denial parsing is separate. Body/stream limits, JSON extraction, bounded response collection, deadlines, and startup gating are the availability boundary. |
| **HTTP health and drain** | Probe requests, drain authorization, and drain trigger | `http::server::build_router` exposes `/healthz`, `/health/live`, `/health/ready`, and `/health/drain`; `startup_gate_middleware` intentionally leaves health paths reachable while reporting non-ready state. `http::routes::health::drain` requires `ResolvedIdentity` with superuser authority. Drain is a lifecycle control, not a data path: `control::shutdown::ShutdownBus`, listener drain guards, and readiness gates stop admission and report state. Deploy the drain endpoint only behind the operator/network controls appropriate for its availability impact. |
| **CDC poll, SSE, and named streams** | Identity, collection/stream names, cursors, offsets, consumer-group commits, SSE reconnects | The transient `/v1/cdc/{collection}` and `/v1/cdc/{collection}/poll` poll/SSE surface uses an opaque, epoch-aware `control::change_stream::ChangeCursor` that preserves publication order and resets on malformed, stale, future, or wrong-epoch input. Durable named streams and consumer groups use `event::cdc::CdcOffset`, a composite `(lsn, sequence)` position whose per-partition commits reject regression and preserve same-LSN siblings. `event::cdc::{StreamRegistry,CdcRouter}` keys durable streams/buffers by `(database_id, tenant_id, stream_name)`. Both token types are positions, never authorization: handlers authorize the collection/source first and apply a token only within that separately authorized database/tenant scope. Buffer retention, polling limits, SSE cancellation, and Event Plane backpressure bound delivery. |
| **WS-RPC and LIVE** | Upgrade headers, bearer credentials, JSON-RPC frames, subscription/filter expressions, live cursors | `http::routes::ws_rpc::ws_handler` is a streaming route; it must resolve the connection identity and route each operation through the same plan/authorization path as HTTP query. `LIVE`/subscription state is scoped to the authenticated identity, database, tenant, and authorized collection; bounded websocket frames, subscriptions, queues, and cancellation prevent an upgrade from becoming an unlimited execution channel. |
| **Native protocol** | Handshake/authenticate messages, MessagePack frames, SQL/operation payloads, streaming chunks | `control::server::native::{handshake,codec,session,dispatch}` and `session_auth::native::authenticate` authenticate before creating a session. MessagePack is decoded with framing and size checks, planned/authorized into capabilities, and dispatched through the SPSC bridge. Native clients do not supply an identity or physical task. |
| **RESP** | TLS/plain TCP setup, `AUTH` credentials, RESP arrays/bulk strings, collection selection, KV/hash/sorted-set/pub-sub commands | `control::server::resp::{listener,codec,session,handler}` parses bounded RESP frames and keeps data operations fail-closed until `AUTH` establishes an `AuthenticatedIdentity`. Command handlers derive the tenant from that identity, use the default database and selected collection, authorize the corresponding read/write task, and dispatch only the resulting capability through `resp::gateway_dispatch`. Connection limits, parser limits, startup gating, and the critical listener drain bound this compatibility surface. Plain RESP must be restricted to a trusted network; use TLS when credentials cross an untrusted network. |
| **ILP** | Mandatory authentication prelude, credentials, line-protocol bytes, tags/fields/timestamps, batches | `ilp_listener::handle_ilp_connection` requires `ilp_auth::authenticate_ilp_connection`; `IlpConnectionAdmission` and `ilp_batch::flush_authenticated_ilp_batch` retain that authenticated database/tenant context. Line and batch parsing must enforce configured line, field, batch, memory, and timestamp bounds before ingestion and authorized dispatch. |
| **Sync** | WebSocket frames, peer credentials, collection/session identifiers, sync operations and presence data | `control::server::sync::{listener,security,wire,session}` authenticates/admit peers and constrains session shape/rate. Sync operations carry the server-derived identity and are authorized against their database/tenant/collection before Data Plane work. Frame and rate limits, plus close-on-invalid-session behavior, provide the boundary. |
| **`/crdt/apply`** | Bearer credential, collection/doc path values, JSON hex delta | `http::routes::crdt::crdt_apply` calls `resolve_identity`, `preflight_crdt_apply`, `decode_bounded_delta`, `authorize_task_set`, and `crdt_admission::dispatch_authorized_crdt_apply_admitted`. The route applies to the default database by design; it does not honor a caller-selected database. `CRDT_HTTP_BODY_MAX_BYTES` and `DEFAULT_MAX_DELTA_BYTES` bound encoded and decoded input; admission applies the external signing/post-image policy and Raft durability gate. |
| **PromQL and remote read/write** | Authorization, PromQL expressions/labels/time ranges, remote-write protobuf/snappy body, remote-read request | `http::routes::promql::*` and `control::promql::{lexer,parser,evaluator,remote_proto}` authenticate and authorize observability access, parse rather than reconstruct expressions, validate selectors/ranges, and enforce request/decompression/result limits before planning or ingest. Remote write/read remain tenant/database-scoped operations, not a bypass around SQL/RBAC. Public build-info is intentionally a health-style informational route. |
| **Metrics** | HTTP scrape request | `http::routes::metrics::metrics` is a monitor-role protected observability endpoint. Its output is operational metadata, so expose it only to trusted monitoring networks and avoid adding secrets, raw credentials, unbounded labels, or tenant data that policy does not permit. |
| **Cluster QUIC and Raft RPC** | QUIC handshakes, peer certificates/SPKI pins, RPC envelopes, Raft log/snapshot frames | `nodedb-cluster::transport::{NexarTransport,TlsCredentials,PinnedClientVerifier,PinnedServerVerifier}` authenticates peers and binds transport identity; `RaftRpcHandler`, Raft message decoding, and replicated state-machine admission validate frame semantics before apply. QUIC flow control and message limits bound transport. Raft storage errors must stop/withhold unsafe progress rather than fabricate state. |
| **SWIM** | UDP membership/probe/gossip packets and membership transitions | `nodedb-cluster::swim::{UdpTransport,MembershipList,SwimHandle}` owns bounded membership processing. SWIM reachability is advisory liveness information; it is not authorization to read, write, or join. Membership changes are reconciled with authenticated cluster/metadata authority before routing or rebalancing changes take effect. |
| **Bootstrap and join** | Join request, one-time token, node ID, CSR/cert/SPKI material, bootstrap response | `control::cluster::bootstrap_listener`, `nodedb-cluster::auth::{verify_token,JoinTokenLifecycle,InMemoryTokenStore,RaftBackedTokenStore}`, and transport `preauthorize_peer_identity` provide one-time/expiry lifecycle and peer-identity binding. Join state is replicated through metadata Raft; failures revoke temporary preauthorization and do not leave a usable member. |
| **Webhook and Kafka egress** | Administrator-created endpoint/broker configuration and event payloads; remote responses | `event::webhook::{WebhookManager,WebhookConfig}` and `event::kafka::{KafkaManager,KafkaDeliveryConfig}` are Event Plane egress consumers. They are created from authorized change-stream metadata, use bounded pending work and drain on shutdown, and never confer ingress authority. Endpoint configuration is security-sensitive: validate scheme/host policy, prevent SSRF according to deployment policy, protect broker credentials, and consider delivered data exposed to the configured recipient. |

### Shared authorization and database binding

The shared authorization boundary is `control::server::shared::authorization`. It maps a physical plan to its required permission (`security::identity::required_permission`), checks tenant, database, collection, role, grants, and policy, and yields an `AuthorizedTask`. `control::gateway` additionally verifies that the capability matches its `QueryContext`. The Data Plane receives the task’s already-bound `database_id`, `tenant_id`, vShard, and plan through `bridge` dispatch; it does not reinterpret headers, claims, or raw client input.

`X-NodeDB-Database` is untrusted selection input. For HTTP query it is resolved by `resolve_database_id` (header, then query parameter, then default); a missing database is an error, not a fallback. Database access is separately checked against the identity and task. The CRDT HTTP apply route is explicitly default-database scoped. Protocols with a session database use the authenticated session context, not a database ID supplied in a payload.

`Authorization` is untrusted credential material, not identity. HTTP resolves JWT/API-key bearer values through `resolve_identity`; other protocols use their own connection authentication. Claims, certificate attributes, API-key scope, and service-account data become authority only after their verifier and server-side provider/principal binding accept them. Do not decode a JWT, MessagePack field, sync field, or SQL parameter into an identity.

`X-On-Deny` is untrusted presentation input. `http::auth::apply_on_deny_header` accepts only trimmed, case-insensitive `SILENT` or `ERROR`; it may request silent filtering or a server-owned generic error for a row-level-security denial. It **only** selects that RLS denial presentation. It cannot grant database, RBAC, or collection access; cannot alter identity, tenant, descriptor, or permission; and cannot bypass authorization or RLS.

## Data and storage boundaries

### Input classes

- **SQL and JSON:** SQL is lexed/parsing-planned by `nodedb_sql`; JSON is deserialized only at the API boundary. Values are validated before plan construction. Never concatenate untrusted identifiers/values into reconstructed SQL; use parser/planner structures and correct identifier/value quoting where SQL generation is unavoidable.
- **MessagePack, native/sync frames, and ILP:** `zerompk`/protocol codecs and line parsers must reject invalid framing, types, lengths, nesting, and batch sizes before allocation. Internal transport uses typed values and MessagePack rather than JSON.
- **PromQL:** lexer/parser/evaluator and remote protocol decoders validate syntax, selectors, ranges, timestamps, samples, and decoded body limits before evaluation or ingestion.
- **CRDT and sync deltas:** validate envelope identity, collection/database binding, delta length, signature/provenance policy where required, constraint/frontier conditions, and replay/idempotency semantics before durable apply.
- **CDC cursor and offsets:** transient `ChangeCursor` tokens carry a publication epoch and sequence; durable `CdcOffset` values preserve both WAL LSN and within-LSN sequence. Per-partition composite offsets avoid acknowledging sibling events. Validate each token's grammar and reset/ordering rules before use; neither token proves stream, database, tenant, or collection authority.
- **Filenames and COPY paths:** file names and paths are untrusted authority requests. Normalize and constrain them to configured, authorized roots; reject traversal, symlink escape, and paths outside the permitted import/export policy before opening files. Never let a client-selected path become an ambient server filesystem capability.
- **WAL, segments, snapshots, catalog, and Raft bytes:** these are untrusted after I/O, restore, crash, media fault, or operator mistake. Format/version/length checks and CRCs detect corruption; recovery, segment quarantine, and startup/readiness gates prevent serving unsafe state. A CRC detects accidental corruption—it is not authentication. AEAD-encrypted tiers and authenticated TLS/QUIC transports provide authenticity/integrity where configured; do **not** claim that every stored byte is authenticated.
- **Cluster frames:** validate peer transport identity before interpreting frame authority, then validate envelope type/version/length, group/node membership, message semantics, and applicable Raft ordering/commit rules. SWIM packets never become data-plane authority on their own.

## Three-plane, recovery, and shutdown safety

The execution model is a security boundary as well as a concurrency design:

- The **Control Plane** owns listeners, credential verification, request parsing, database selection, SQL/PromQL planning, RLS context construction, authorization, and authorized capability dispatch.
- The **Data Plane** is `!Send`, performs physical execution and storage I/O, and accepts only admitted work through bounded SPSC bridge envelopes. It must not turn raw network input into physical work or invoke Control/Event Plane facilities directly.
- The **Event Plane** receives committed `WriteEvent`s through per-core bounded rings and owns CDC, triggers, scheduling, webhook/Kafka delivery, consumer offsets, and its durable watermarks/state. It does not execute raw client physical storage operations; side effects that need user-data work re-enter through the authorized Control-to-Data path.

The Event Bus is WAL-backed. If an Event Plane ring is saturated or a consumer restarts, `event::wal_replay` reconstructs events from durable WAL rather than making the Data Plane wait indefinitely. CDC routing maintains database/tenant/stream keys and offsets so replay cannot silently change scope. This recovery property does not turn CDC into exactly-once delivery to external systems; consumers and egress targets must tolerate retries according to their delivery contract.

Phased shutdown is coordinated by the canonical `control::shutdown::ShutdownBus`, listener drain guards, `EventPlane` shutdown, the strict `LoopRegistry` supervisor, and startup/readiness gates. The server first stops or rejects new work, drains critical listeners and bounded in-flight work, joins Event Plane consumers and delivery managers, then persists final watermarks and closes WAL. Abort-safe tasks may be aborted at their configured deadline; correctness-critical no-abort and blocking loops retain ownership and hold the phase until they reach a safe termination boundary. The first OS signal waits for the canonical bus to reach `Closed`; only a second signal force-exits the process. On startup, health readiness remains false until recovery prerequisites—including WAL recovery—are satisfied.

## Deployment assumptions and residual risks

This model relies on operational controls that source code cannot provide by itself:

- **Trust and insecure cluster modes:** Trust-mode client authentication and insecure cluster transport are private-network guardrails, not Internet-safe modes. `insecure_transport_bind_allowed` restricts insecure cluster binding to private/local addresses; operators must still enforce network isolation and never expose these listeners publicly.
- **Bearer and session theft:** A stolen bearer token, API key, or authenticated client session can act within its grants until expiry/revocation. Use TLS, short expirations, key rotation, revocation, least privilege, and secure client storage.
- **JWKS availability and staleness:** OIDC/JWKS verification depends on configured issuer/audience/keys and cache/refresh behavior. Plan for provider outage, key rotation, clock correctness, and the trade-off between availability and accepting stale cached keys.
- **Keys and backups:** Encryption is only as strong as KMS/key-file permissions, TLS private-key protection, secrets handling, and backup/snapshot access controls. Protect keys independently from encrypted data; test restore and key-rotation procedures.
- **Authenticated cluster-member compromise:** mTLS/pinning proves membership, not benign behavior. A compromised authorized member can affect replicated operations within its authority; use hardened nodes, restricted membership/join-token handling, audit, monitoring, and rapid credential/node revocation.
- **Denial of service within configured caps:** Size, queue, connection, and rate limits bound resource use but do not eliminate CPU, network, disk, connection-exhaustion, or expensive-query DoS. Set caps for workload and isolate public endpoints.
- **Legacy migrations and restored data:** Older catalog/WAL/segment/snapshot formats and migration code expand the parsing attack surface. Validate backups, preserve compatibility tests, and fail safely on unknown/corrupt data.
- **Egress endpoints:** Webhooks, Kafka brokers, alert targets, and OTLP-style destinations can receive authorized data and can be abused for SSRF or resource consumption if configuration is not restricted. Apply outbound network policy, endpoint allowlists, credential isolation, TLS verification, delivery limits, and payload minimization.
